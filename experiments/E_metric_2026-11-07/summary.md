# E-metric · SSIM/L2 裁决：等 w·s 的失败是结构性的

**日期**：2026-11-07 09:06–09:29（23 min，288 图）
**脚本**：`exp/p2/e_metric.py`　**日志**：`run_emetric.log`　**明细**：`csv/emetric_images.csv`（288 行）
**素材**：同 L2（SD1.5 + `lora_detail_sd15` + CLIP ViT-L/14）

## 为什么做这个

§8.6 的四度量分析留下一个无法内部裁决的矛盾：

- `pix_l2` 给 `geff_const` **−6.3%**（p=9e-18，显著）
- `clip_i_ref` 给 **−0.0003**（p=.11，不显著）
- `clip_i_base` 给 **+0.0050**（p=1.7e-10，**反向**）

而 `pix_l2` 是 **64×64 缩略图的 L2**。`ws_equal` 在 w=0.2 时要求 s=37.5（网格上限 14 的 2.7 倍），画面严重过饱和——**缩略图 L2 可能只是在嫌它亮，不是在嫌它不像**。如果成立，「等 w·s 错」这个核心负结果就建立在色调伪影上。

所以重新渲染一批图（**不依赖 L2 的任何中间产物**），在**同一批像素**上算五个度量。

## 设计

- **prompt**：object / person / style 各 2 个（共 6），文本与 L2 相同
- **seed**：11、22（2 个，使胜率不是单次抽样）
- **图**：每 (prompt, seed) 渲染 2 个锚点（原模型 w=0、参考 w₀=1 s₀=7.5）+ 3 路线 × 8 w = **26 图**
- **合计**：6 × 2 × 26 = **312 图**（CSI 上 288 张路线图被计入配对）

| 度量 | 定义 | 方向 |
|---|---|---|
| `pix64` | 64×64 缩略图 L2（复现 L2 的口径） | 小=近 |
| `pix512` | **全分辨率 512² L2**（归一化到 [0,1]） | 小=近 |
| `ssim` | **SSIM，512² 灰度**，skimage 默认 7×7、data_range=255 | **大**=近 |
| `clip_i_ref` | cos(image, 参考图) | **大**=近 |
| `clip_t` | cos(text, image) | **大**=近 |

## 三条结论

### 1 ✅ 「等 w·s 明确错」是**结构性的**，不是色调伪影

`ws_equal` 的 **SSIM 只有 .699，比 fixed_s 的 .816 低 14.4%**，配对胜率仅 **16.7%**（即 fixed_s 有 83% 概率更好）。

**这排除了唯一的替代解释**：如果 pix 端的劣势只是"过饱和导致缩略图整体漂移"，那 SSIM（灰度、全分辨率、对亮度偏移做了局部归一）**不应该看到这么大幅度的下降**。它看到了。

→ **这条负结果现在是全文最硬的一条**，可以在正文里正面写：**等 w·s 换算不只是"看起来不一样"，是结构性破坏**。

### 2 ⚠️ 「我们的补偿更好」方向一致，但**效应量按度量严格程度单调递减**

| 度量（从严到松） | geff 相对 fixed 的改善 | 胜率 |
|---|---|---|
| clip_i_ref（语义） | **+0.23%** | .552 |
| SSIM（结构） | **+1.13%** | .646 |
| pix512（全分辨率外观） | **+6.80%** | .698 |
| pix64（缩略图外观） | **+9.81%** | .698 |

**这个梯度本身就是结论**：补偿主要在**低层外观**（色调、亮度分布）上起作用，对**高层语义**几乎不动（+0.23%）。

→ **正文必须四个数一起报**。只报 +9.81% 是选择性报数，审稿人用 CLIP 一比就露。

### 3 ❌ `clip_t` 不只是无分辨力——它与保真度**负相关**

三路线差 < .001、配对胜率 .406–.427（几乎随机）。本设置下 cos(text, image) 只在 .277–.292 之间浮动。

**秩相关矩阵（同一批 288 图）**：

| | pix64 | pix512 | ssim | clip_i_ref | clip_t |
|---|---|---|---|---|---|
| pix64 | 1.000 | **.976** | .901 | .781 | **−.092** |
| pix512 | .976 | 1.000 | **.935** | .699 | **−.182** |
| ssim | .901 | .935 | 1.000 | .714 | **−.214** |
| clip_i_ref | .781 | .699 | .714 | 1.000 | .297 |
| clip_t | −.092 | −.182 | −.214 | .297 | 1.000 |

三条读法：

1. **pix64 ↔ pix512 = .976** → 缩略图 L2 与全分辨率 L2 **几乎是同一个量**。"缩略图会骗人"这个疑虑**本身不成立**。
2. **SSIM ↔ 两者 = .90 / .94** → 结构度量与像素度量高度一致，**pix 端的结论不是像素特有的**，加固结论 1。
3. **`clip_t` ↔ pix/SSIM 全部为负（−.09 ~ −.21）** → 它测的是**提示词遵从度**，不是保真度。个性化 LoRA 里 w 增大会让风格更强，**可能同时"更像参考"和"更不像提示词"**。→ **CLIP-T 不能充当"更严格的保真度指标"，它与保真度方向相反**，方法节必须声明。**这是本次最重要的方法学发现。**

## 一次自我纠错：`clip_i_base` 不该进裁决

§8.6 曾写下："`geff_const` 在 `clip_i_base` 上反而更差（+0.0050，p=1.7e-10）→ 不能写补偿更接近参考图。"

**这个推理是错的。**

`clip_i_base = cos(image, w=0 的图)`，量的是**离原模型多远**。而补偿的目标是"**把 w 缩放到 2 之后，输出仍等于参考强度 (w₀=1, s₀=7.5) 的效果**"——**它本来就该离原模型更远**，因为 w 变了。

用 `clip_i_base` 否定补偿，等于用"离题目标更远"证明"离正确答案更远"，**混淆了两个不同的目标**。

**正确处理**：`clip_i_base` 只作**副作用**报告（"补偿使输出更偏离原模型，幅度 0.005 cos，符合预期"），**不进"是否更接近参考"的裁决**。四个真正的"离参考"度量（pix64 / pix512 / SSIM / clip_i_ref）**方向全部一致支持 geff**。

## 限制（诚实标注）

1. **只有 6 prompt × 2 seed**（96 配对/度量）。跨 LoRA 类型完全未测（E2c-2 阻塞：本地只有 1 个 SD1.5 LoRA）。
2. **SSIM 的绝对差很小**（.8252 vs .8160 = 1.13%）。但这不是插值误差——本实验是**直接渲染后配对**，没有 §8.5 那 0.18 的网格插值误差。**所以 +1.13% 是真的，只是小。**
3. **`ws_equal` 在 w=2.0 反超**（pix64 9.63 vs geff 10.28；SSIM .6133 vs .6207 仍略差）——与 §8.5 的分段 κ（w≥1.2 段 ≈.94）一致，**是分段结构的直接体现，不是噪声**。
4. **未做感知度量（LPIPS/DINO）**：DINO 权重未下载。CLIP-I 是替代，不等价。
